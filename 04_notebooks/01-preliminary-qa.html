Make column names R-friendly

This is a simple step using the janitor package which converts the column headers to a more code-friendly format. This helps when writing the rest of the code. Note, when I first read in the data, I stored it in the variable inventory_raw. I always keep a copy of the raw, unprocessed data in a variable with the _raw suffix so that I can compare the results of any cleaning actions against the original data. Now that I am starting to clean the data, I store it in a new variable called inventory_clean.

# Clean the column names
inventory_clean <- inventory_raw |> 
  clean_names()

Check variable types

Looking at the output from glimpse() above, I notice the following issues:

  • The stock_date column is incorrectly stored as a character variable. This should be stored as a date.
  • The product_id_sku column is incorrectly stored as numeric. This should be a character variable.

I’m curious about the stock_date column. The values that we can see from glimpse() all look like numbers but are stored as text. If the entire column were numbers, then R would have read this in as numeric. Let’s take a closer look at all of the distinct values in this column.

OK, so there are some values where the date has been entered as a text string. To fix this and convert all the values to dates, I’ll need to use the lubridate and janitor packages and fix this in two steps. The key is to first try parsing the dates in the dd-mmm-yy format using lubridate::dmy(). If that fails (which it will for the numeric strings), I then process those failed cases as Excel numeric dates using janitor::excel_numeric_to_date().

# Fix the incorrect variable types
inventory_clean <- 
  inventory_clean |> 
  mutate(
    stock_date = if_else(
      is.na(dmy(stock_date)),
      excel_numeric_to_date(as.numeric(stock_date)),
      dmy(stock_date)
    ),
    product_id_sku = as.character(product_id_sku)
  )

Looking at the ranges in this summary I notice the following:

  • Unit prices range from 0 to 375. The histogram shows that the 375 is a real outlier, and knowing what this business sells it’s unlikely that there would be a true unit price of 375. It’s more likely that this should be 3.75.
  • There shouldn’t be any products with a 0 unit price either. These will need to either be imputed or removed from the dataset. Since I don’t know what the correct value is, I will convert the 0 to NA for the time being.
# Correct the unit prices where necessary
inventory_clean <- 
  inventory_clean |> 
  mutate(
    unit_price = case_when(
      unit_price == 0 ~ NA,
      product_id_sku == "80961" ~ 3.75,
      TRUE ~ unit_price
    )
  )

# Fix spelling errors in categories
inventory_clean <- 
  inventory_clean |> 
  mutate(category = str_trim(category)) |> 
  mutate(
    category = case_when(
      category == "Cookies Snacks & Candy" ~ "Cookies, Snacks & Candy",
      category == "Frozen Food" ~ "Frozen Foods",
      category == "Fruits & Vegtables" ~ "Fruits & Vegetables",
      TRUE ~ category
    )
  )
